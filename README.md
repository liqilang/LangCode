## 它是什么

平时用 AI 写代码，常见的问题是：它看不到你的项目、只能把代码贴给你、你得自己复制粘贴。LangCode 解决的就是这个问题。

它作为一个**工具窗口**嵌在 Visual Studio 里，可以：

- 自己打开你的文件、搜索你的代码、看懂你的项目结构；
- 直接把改动写进你的文件（**改之前一定先给你看差异**）；
- 帮你运行命令、跑测试、甚至操作浏览器自测；
- 你随时可以叫停、拒绝，或一键还原到之前的版本。

## 它能做什么

下面按「你实际会用它干的事」来讲，而不是按技术名词。

### 💬 1. 像一个懂你项目的助手一样对话

直接用中文（或英文）描述你想做的事，例如「帮我把登录页的表单校验加上」「这个报错是什么原因」。它能自动带上你**当前打开的文件**、**选中的代码**和**编译错误信息**，不需要你每次手动复制。

### 🔍 2. 帮你读代码、找代码

项目大了不好找东西？可以直接问：

- 「用户登录的逻辑在哪个文件？」
- 「`CalculateTotal` 这个方法被哪些地方调用了？」
- 「`IUserService` 有哪些实现类？」

它会用自己的搜索能力（关键词搜索、语义检索、符号查找）快速定位，再把相关的代码片段读给你看。

### ✏️ 3. 直接帮你改代码（改之前先给你确认）

这是它最核心的本事。它不止给建议，而是**真的动手改文件**：

- 小改动：局部替换；
- 大改动 / 跨文件重构：一次改多处；
- 按「符号」改：比如「把 `Login` 这个方法的内部重写一遍」，不用你抄原代码；
- 批量重命名：把某个类 / 方法 / 变量的名字一次改到所有引用处（自动跳过字符串和注释）。

**重要**：每一次写文件，它都会在窗口里显示一张**差异卡**，把「加了几行、删了几行」标得清清楚楚，你点「应用」它才真正保存。不满意就点拒绝。

### 🖥️ 4. 帮你跑命令、跑测试

需要装依赖、构建项目、跑测试？它可以在你的工作区里执行命令，比如 `npm install`、`dotnet build`、`npm test`。

它还会**自动识别你的项目类型**（.NET / Node.js / Python / Rust / Go …），所以「跑一下测试」这种模糊的指令它也知道该敲哪条命令，跑完把结果读回来分析。

> 出于安全，危险命令（删盘、格式化、清空系统目录等）会被直接拒绝；命令执行前默认也要你确认。

### 🌐 5. 前端自测 / 浏览器自动化

做 Web 开发时，它可以打开你本地的开发地址，做导航、点击、填表单、执行脚本、截图、读取浏览器控制台的报错。适合「改完前端想快速看一眼有没有白屏 / 报错」的场景。

### 🐞 6. 调试器联动

调试状态下，它可以帮你：

- 看看断点、调用栈、当前各个变量的值；
- 求值某个表达式（比如 `user.Name` 是什么）；
- 设置 / 删除断点，继续、单步、暂停、停止。

等于把一个「会看调试器状态的助手」放在身边。

### 🔌 7. 接入 MCP 工具（让它能力可扩展）

MCP 是一套「给 AI 用的工具协议」。你可以在设置里连接各种 MCP 服务器（文件系统、数据库、GitHub 等等），连接后 AI 就能调用这些能力。它还支持**从别的 AI 工具一键导入**已有的 MCP 配置，不用重配。

### 🧠 8. 长任务编排：任务清单、子任务、主动提问

任务一多，它不会闷头乱做，而是把过程变得可见、可控：

- **任务清单**：用 `update_todo_list` 列出「要做哪几步」，状态分为待办 / 进行中 / 已完成；窗口顶部有常驻进度条，完成一项更新一项。
- **子任务**：某块工作相对独立、本身又需要多步时，用 `new_task` 拆出去独立完成，做完把结论带回主线；同一轮拆多个子任务时会**并行执行**。
- **主动提问**：需求不明确时用 `ask_followup_question` 停下来问，备选答案可以直接点，也可以自由回答或跳过。
- **计划模式**：输入框下方点「计划」，它只调研、出分步计划，不改任何文件；确认后切到「执行」再动手。

### ⏪ 9. 后悔药：检查点 / 一键还原

它会在改动前偷偷记一个快照。如果改得不满意，可以**还原到之前某个时间点**，不用担心把代码改乱。

### 🧩 10. 自由换模型

想用哪家的 AI 就用哪家的：国内的 DeepSeek、kimi、通义千问、智谱，国外的 OpenAI、Anthropic、Gemini、Grok，或者跑在自己电脑上的 Ollama / LM Studio（免费、不联网）。还可以把多套配置**命名保存**（比如「公司网关」「本地模型」），随时切换。

## AI Agent 是怎么工作的

LangCode 的核心不是一个「问答接口」，而是一个 **Agent 循环**：

```text
你的需求
  → 带上系统提示词、工具清单、项目规则与自动上下文
  → 模型决定「直接回答」还是「调用工具」
  → 执行工具，把结果回灌给模型
  → 模型继续调用或给出最终答复
```

几个关键点：

- **动作块**：模型用 ` ```action ` 代码块发出工具调用（JSON）。一次可以发多个互不依赖的动作，减少往返。
- **有工作区权限**：能读文件、搜代码、按符号改写、多文件补丁、跨文件重命名、跑命令、跑测试、操作浏览器、查看调试器。
- **原生 function calling**：可选开启；OpenAI 兼容与 Anthropic 原生两种 `tools` 格式都支持。
- **改完还能跑通**：本轮真的改过文件时，会自动跑验证命令；失败时把输出回灌；还能读取 Visual Studio「错误列表」自动修复，最多 N 轮。
- **计划模式**：只向模型暴露只读工具，并在运行时拦截破坏性动作，适合先出方案再执行。

完整的循环、上下文压缩、费用控制与安全机制见 [AI 与自动化能力总览](docs/ai-agent.md)。

## 长任务编排：任务清单、子任务与提问

| 能力     | 工具                      | 界面                                    | 说明                                                 |
| -------- | ------------------------- | --------------------------------------- | ---------------------------------------------------- |
| 任务清单 | `update_todo_list`        | 对话里的「任务进度」卡 + 窗口顶部进度条 | 每次整体替换；`[ ]` 待办、`[-]` 进行中、`[x]` 已完成 |
| 子任务   | `new_task`                | 「子任务」卡，子任务内部卡片缩进一格    | 独立跑一轮，完成后把自然语言结论带回父任务           |
| 主动提问 | `ask_followup_question`   | 提问卡 + 请求条                         | 选项可点击；也可自由输入；不想答可「跳过回答」       |
| 计划模式 | 输入框「计划 / 执行」芯片 | 只读调研 + 分步计划                     | 计划阶段不改文件、不跑命令；确认后切执行             |

### 子任务是怎么跑的

1. 父任务判断某块工作相对独立、且本身需要多步，调用 `new_task`，传入 `task` 与可选 `context`；
2. 插件创建一个子 Agent，带着同一套后端、工作区、设置与会话 id 独立跑一轮；
3. 子任务内部产生的工具卡片（读文件、改文件、差异卡等）照常显示，但在界面上缩进，表示它们属于这个子任务；
4. 子任务「不带动作」的那一轮文本会作为结论，回灌给父任务；
5. 父任务继续执行，或根据结论调整计划。

**限制与特点：**

- 子任务**最多一层**，不能在子任务里继续拆子任务；
- 同一轮里出现多个 `new_task` 时，顶层任务会**真并行**执行，再按原顺序收集结果；
- 并行子任务同时请求审批 / 提问时，界面会串行化，一次只显示一张；
- 自动验证 / 自动修复只在顶层任务执行，子任务内不重复跑；
- 一句话就能做完的事不要拆子任务，直接调用对应工具更省。

## 快速开始

### 环境要求

| 项目 | 要求                              |
| ---- | --------------------------------- |
| 系统 | Windows 10 / 11                   |
| IDE  | Visual Studio 2022（17.0 及以上） |
| 框架 | .NET Framework 4.7.2              |

### 安装

**方式一：在 Visual Studio 里直接搜索安装（推荐）**

1. 打开 Visual Studio 2022；
2. 顶部菜单栏选择 **扩展 → 管理扩展**（Extensions → Manage Extensions）；
3. 在左侧切换到 **联机 / Online**，在右上角搜索框输入 `LangCode`；
4. 在搜索结果里找到 **LangCode**，点击 **下载 / 安装**；
5. 按提示关闭 Visual Studio，安装程序会自动完成安装，重新打开 Visual Studio 即可使用。

**方式二：使用 VSIX 安装包**

1. 下载 / 构建得到 `LangCode.vsix`；
2. 双击按提示安装（也可以把 VSIX 放进 `%VSINSTALLDIR%\Common7\IDE\Extensions\` 手动部署）；
3. 重启 Visual Studio。

### 配置并使用

1. 打开工具窗口：菜单 **工具 → 打开 LangCode**（也可以在代码窗口右键 → **LangCode**）；
2. 在**设置**里选一个「API 提供商」，填入你的 API Key（用本地模型可留空）；
3. 选一个模型（下拉里可选，也可以直接输入模型名）；
4. 在输入框里描述你的需求，回车开始。

## 怎么用

### 直接对话

在输入框里正常打字即可。它会自动感知你当前打开的文件和选中的代码。

### 用 `@` 提及文件

输入 `@` 可以快速指定某个文件，让 AI 重点看它。

### 用 `/` 呼唤常用指令

在输入框里输入 `/` 会弹出命令列表：

| 命令       | 作用                                     |
| ---------- | ---------------------------------------- |
| `/plan`    | 先别动代码，只做调研并给出分步计划       |
| `/review`  | 审查你还没提交的改动，按严重程度列出问题 |
| `/commit`  | 按规范生成提交信息                       |
| `/test`    | 为最近改动的代码补单元测试               |
| `/fix`     | 先说清根因，再给最小改动                 |
| `/explain` | 解释一段代码的作用和坑                   |
| `/clear`   | 清空当前会话（历史仍在）                 |

### 代码窗口右键菜单

选中一段代码，右键 → **LangCode**，可以：

- **解释选择**：讲清楚这段代码在干嘛；
- **重构选择**：帮你重构；
- **生成测试**：补单元测试；
- **生成文档**：补注释 / 文档；
- **修复选择**：定位并修问题；
- **内联编辑（Ctrl+K）**：在光标处直接改，改完就地替换。

### 常用快捷键

| 快捷键   | 作用         |
| -------- | ------------ |
| `Ctrl+K` | 选区内联编辑 |

## 安全与隐私

这一块设计得比较克制，核心就一句：**动你东西之前，先问你。**

- **写文件要确认**：每一次修改代码都会生成差异卡，你确认才落地；
- **命令要确认**：执行终端命令前默认会询问；危险命令直接拒绝；
- **可按类别放行**：如果你嫌确认太频繁，可以在设置里分别放行「读取 / 编辑 / 新增 / 命令 / 浏览器 / MCP」这几类操作，让某一类不用再问；
- **计划模式**：开启后 AI 只能看、不能改，适合先让它给方案；
- **检查点**：改动前自动留快照，随时可还原；
- **只动你的工作区**：所有文件操作都限制在项目目录内。

## 数据存在哪里

所有数据都放在你本机，路径为 `%APPDATA%\LangCode\vsext\`：

| 内容             | 说明                                                           |
| ---------------- | -------------------------------------------------------------- |
| `settings.json`  | 你的所有设置；API Key 使用 Windows DPAPI 加密后落盘            |
| `conversations\` | 历史会话：每个会话一个 JSON 文件，另有 `index.json` 元数据索引 |
| `usage.jsonl`    | 每次模型调用的 token 用量与费用（按会话归集）                  |
| `checkpoints\`   | 检查点影子仓库（git），用于把文件还原到某一轮之前              |
| `audit.log`      | 工具调用日志（默认关闭，开启后才有；超过 2MB 自动轮转）        |

想重置设置就删掉 `settings.json`；想清空历史就删掉 `conversations` 目录；想同时清掉检查点就删掉 `checkpoints` 目录。

## 常见问题

**没有打开解决方案 / 文件夹，能用吗？**
能，但本轮按纯对话处理，不会读写文件。打开项目后再发一次即可启用文件工具；也可以在新会话里按提示选择一个目录作为工作区。

**为什么改文件还要我点「允许」？**
这是 LangCode 的安全承诺：写文件前先给你看差异，你确认才落盘。如果嫌频繁，可以在输入框的 **Auto** 芯片或设置页里按类别放开「读取 / 编辑 / 新增 / 命令 / 浏览器 / MCP」。

**子任务能无限嵌套吗？**
不能。子任务最多一层；在子任务里再调用 `new_task` 会被拒绝。这是为了避免「谁在等谁」变得不可读，也避免空转。

**计划模式能保证绝对不改文件吗？**
计划模式只向模型暴露只读工具，并在运行时拦截破坏性动作；执行阶段仍然有审批、命令安全策略和检查点。三层保护互相独立，不能互相替代。

**检查点需要本机安装 git 吗？**
需要。检查点用影子 git 仓库保存快照；本机没有可用的 `git` 时，检查点会优雅失败，其他能力不受影响。
